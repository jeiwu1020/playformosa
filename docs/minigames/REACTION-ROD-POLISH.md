# 接棒啦：結算焦點與桌面版面修整候選版

基底是已發布的 `preview/hurdles` 提交 `ba0145c3bad717474689090e3049c3905ba1fd08`。本次是隔離候選來源，尚未推送或部署；`main` 不變。

## 修整內容

- 僅移除接棒結算大標題的焦點外框。標題仍是結算開啟時的讀屏起點，對話框名稱與焦點管理不變；按鈕、連結、上傳展開列及暱稱欄仍有清楚的鍵盤焦點。
- 電腦與既有寬橫向版型維持左照片、右操作。右側改為成績、兩排主要操作、分享、手動上傳的單一連續內容，避免左圖高度把成績和按鈕拉開。
- 照片左右深綠邊來自共用 canvas 元素底色與 contain 留邊，不在凍結的照片像素裡。寬版改為透明底色、自然比例及有上限的顯示高度；不裁照片、不重新截圖、不改攝影機。
- 手機窄版視覺順序保持成績、照片、主要操作、分享、手動上傳。小畫面、放大字體或展開內容仍可捲動，不以縮小操作區硬塞一頁。
- 上傳面板只建立一次，移到接棒專用插槽。共用介面的 `resultUploadContainer` 預設仍是原 result，因此其他八款維持原位置。原上傳狀態、暱稱、手動提交及自動捲動安全機制皆沿用。

## 保護範圍

只有四個執行來源修改：接棒 `index.html`、`game.mjs`、`result.css`，以及共用 `leaderboard.mjs`。接棒控制器只有上傳插槽參數一處差異。坐倒、物理、輸入、判定、重播、定格、分享圖片及後端均不改。459 個其他執行來源、資料、資產與歷史清單逐位元組保留。

新的精確可逆清單先回復至本次基底，再讓舊的重播、結算及 viewport 清單核對原始版本。舊清單未覆寫，也未放寬來源驗證。

## 檢查與限制

- 先以原版本執行新增測試，確認標題框、右側內容容器及上傳位置缺失會失敗，再完成修改。
- 窄版及寬版 CSS 規則、焦點、照片完整呈現約束、缺圖降級、九款上傳區、暱稱保留、鍵盤輸入、暫停／重播往返、取消舊捲動均有測試。
- 獨立審查沒有阻擋問題。另驗證排行榜、上傳展開、暱稱、提交與關閉控制的可見焦點。
- 照片在 DOM 閱讀順序位於右側內容之後；手機的視覺順序由 CSS 保持。鍵盤互動順序沒有改變，照片沒有互動控制。這是已知的非阻擋讀屏呈現差異，沒有用不可靠的 ARIA 重新排序來掩蓋。
- 自動檢查使用 JSDOM、真實控制器與 CSS 規則；不等於實際裝置像素、原生鍵盤模式或讀屏實測。雲端瀏覽器沒有 WebGL，且無法開啟這份隔離候選；沒有重試此前遭限制的本機瀏覽器操作。
- 最終完整檢查：1,411 項通過、0 失敗、0 跳過；建置及 preview 檢查通過，438 輸出檔案的 506 本地引用有效。完整來源另做獨立還原檢查；備份及還原結果另存完成紀錄，測試證據隨來源備份。

## 預覽驗收建議

1. 手機和電腦結算時，大標題不再出現綠框；使用 Tab 時可辨識操作焦點。
2. 電腦照片完整、不再有深綠填補邊，右側操作和上傳在一起；手機窄版順序與原來相同。
3. 展開上傳會帶入視野，不直接彈出鍵盤或送出成績。輸入暱稱後重播、回來、開排行榜再返回，內容都保留。
4. 放大文字、短橫向、缺圖或展開細節時仍能捲到全部控制，不裁掉棒子或提交按鈕。

發布仍需另行確認分支並核對最新遠端頭；不要整包覆蓋分支或改動 main。
