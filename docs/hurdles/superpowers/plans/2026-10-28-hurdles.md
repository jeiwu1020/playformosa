# Hurdles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** Deliver a complete private standalone four-limb hurdles game.
**Architecture:** Buildless ES modules; deterministic fixed-step physics independent of DOM; exact existing Three.js character consumes joint endpoints; responsive UI, audio and share adapters.
**Tech Stack:** JavaScript, Canvas/WebGL, vendored Three.js, Node test runner.
**Spec:** docs/DESIGN.md

## Global Constraints
- Never edit PlayFormosa GitHub/production; new isolated private Sites only.
- Same character.mjs, J left arm, K right arm, A left leg, S right leg.
- Actual pose-derived hurdle collisions; ten hurdles / 110m; finish time primary.
- Preserve licenses and source/hash manifest before deployment.

## Review Focus
1. Held input on pause/rotation must not launch on resume.
2. Same-key spam / all-key hold cannot produce automatic victory.
3. Low/trailing limbs actually contact and topple hurdles.
4. Screenshot remains stable after restart and pending export cannot leak previous result.
5. Narrow/short mobile viewport must keep arena and usable controls.

## Tasks
- [ ] Physics: tests first for acceleration, charging, held input, swept collisions, recovery, full finish and timeout; implement physics.mjs and verify all tests.
- [ ] Presentation: exact character plus course scene, camera framing, same-scene software renderer; test pose bone lengths and bounds. Visual review browser.
- [ ] Interaction: tests first for multi-pointer/key independence, cancel, pause. Build responsive controls and overlays.
- [ ] Audio/share/result: tests first for bounded facts and share fallback semantics; implement and inspect full result export. Reuse audio with complete provenance.
- [ ] Validate full replay, browser layout and console. Archive source+assets+license+manifest+hash; save Library backup. Push via Sites helper, publish owner-private; verify exact deployed version.

## Completion ledger
- Physics, scene, input, responsive UI, audio, share, result tasks completed. See QA.md.
- Ruling: keep source-owner-private Sites workflow, not GitHub integration. The new Site owns its own source repository; this does not edit PlayFormosa main.
- Ruling: WebGL-disabled cloud browser uses software renderer of exact same scene/mesh; this permits real input/visual QA without claiming WebGL validation. Cost: software lighting differs and is lower fidelity than PBR, documented honestly.
- Final reviewer fixes: mobile native-share rejection fallback and accessible control activation; 29/29 suite green. No deferred critical/important findings.
